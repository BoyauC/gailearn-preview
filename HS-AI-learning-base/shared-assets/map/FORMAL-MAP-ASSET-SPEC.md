## 1. 製作基準

- 設計座標採 `1920 × 1080`、16:9 橫向畫布。
- 平板橫向為主要檢查尺寸，桌面等比例放大；手機以縮放與安全區調整，不另畫一張不同配置地圖。
- 正式場景滿版延伸，不使用橢圓土地或外圍空白底色。
- 四棟建築維持 v5 的相對比例與位置；正式輸出不得把人物烘焙進地圖。
- 概念稿只供構圖、比例、色彩與物件位置參考，不直接作為碰撞底圖。

## 2. 正式圖層

由下到上依序為：

1. `terrain-base`：草地、沙土地、基礎色差與不可互動的細小地面紋理。
2. `terrain-details`：僅保留必要且不需與建築對齊的地面細節；左側廣場以獨立素材放置。
3. `building-back`：建築後牆、室內地板、後側家具及不會遮住人物的固定量體。
4. `building-solid`：主要牆體、門柱、設備及建築碰撞對應物。
5. `player-ring`：腳邊可見橢圓光環。
6. `player-shadow`：人物陰影，與光環分開控制。
7. `player-body`：阿岳本體、書包、徽章及裝備圖層。
8. `building-foreground`：人物走到建築後側時會遮住人物的前牆、屋簷、樹冠與高植栽。
9. `effects`：入口提示、授章、通關與互動效果。
10. `ui`：進入挑戰對話框、回到廣場與進度介面。

## 3. 地圖輸出清單

| 檔案 | 格式 | 透明 | 用途 |
|---|---|---:|---|
| `terrain-base.webp` | WebP | 否 | 全畫面地貌底圖 |
| `plaza.webp` | WebP | 是 | 左側廣場獨立素材 |
| `boundary-back.webp` | WebP | 是 | 後側圍籬、花台與樹木 |
| `boundary-front.webp` | WebP | 是 | 前景樹冠與遮擋物 |
| `map-layout.json` | JSON | — | 建築、廣場、出生點與安全區座標 |
| `collision-map.json` | JSON | — | 建築碰撞、地圖邊界及互動區資料 |

- 正式 WebP 原則上以 `1920 × 1080` 座標對齊輸出；透明圖層可裁切，但必須附原點與放置座標。
- 不把房名、網址、GA 標題、對話框或操作提示畫進地圖圖片。
- 不製作四房入口道路、入口地磚或預先對齊的建築基座；建築可在連續草地／沙土地上獨立安放，避免日後調整位置時必須同步重畫地面。

## 4. 單棟建築輸出

每棟建築分別建立：

```text
buildings/<room>/formal/
├─ building-back.webp
├─ building-solid.webp
├─ building-foreground.webp
├─ building-shadow.webp
└─ building-layout.json
```

`<room>` 使用四個固定房間素材名稱：

- `filter-bubble`
- `sift-detective`
- `collaboration-director`
- `companion-designer`

建築正式圖層不得包含尺度人物、房名文字、碰撞線框或入口提示。

## 5. 四棟位置與入口方向

| room_id | 地圖位置 | 主入口方向 | 主要前景遮擋 |
|---|---|---|---|
| `filter_bubble` | 左下 | 朝中央／右前 | 前側弧牆、局部窗框與低植栽 |
| `sift_detective` | 上方中段 | 朝中央／下前 | 門框、前牆與局部設備 |
| `collaboration_director` | 右下 | 左前、朝中央 | 場記板、入口雨棚與前牆 |
| `companion_designer` | 右上 | 左前、朝中央 | 前右五問面板、門柱；右後植栽靠地圖邊緣 |

- 四房之間不建立道路或預設路線。
- 不設入口踏板或道路；門前可由地貌底圖既有的自然磨損與色差銜接，但不得形成固定路線或要求建築精確對齊地磚。
- 左側廣場是一般出生與返回位置，不稱為中央廣場。

## 6. 人物比例、原點與光環

- 人物顯示比例以 v5 校正稿為準，約為 v4 尺度人物的 2 倍。
- 所有待機、步行、互動及裝備影格使用相同可見高度基準，不得因換格產生縮放跳動。
- 人物座標原點固定為雙腳接地中心。
- 可見光環為斜俯視橢圓細環，位於人物與陰影下方；移動時顯示，停止時可降亮度。
- 光環動畫只能改變透明度、亮度或局部流光，不縮放人物，也不移動人物原點。
- 正式畫面不顯示碰撞圓、房門觸發區或排序線。

## 7. 碰撞與互動資料

三種判定必須分開：

1. `player_footprint`：以腳底中心建立的小型隱形圓／橢圓，處理牆體與障礙物碰撞。
2. `building_solids`：建築可阻擋區，可由多個簡單多邊形組合，不用整棟外接矩形。
3. `door_trigger`：門前較大的互動區，只負責顯示「進入挑戰」與接受 Enter／點擊確認。

建議資料格式：

```json
{
  "roomId": "sift_detective",
  "assetOrigin": { "x": 0, "y": 0 },
  "sortBaselineY": 0,
  "buildingSolids": [
    { "type": "polygon", "points": [[0, 0], [0, 0], [0, 0]] }
  ],
  "doorTrigger": {
    "type": "ellipse",
    "x": 0,
    "y": 0,
    "radiusX": 0,
    "radiusY": 0
  },
  "doorApproach": { "x": 0, "y": 0 },
  "entrySpawn": { "x": 0, "y": 0, "facing": "right" },
  "returnSpawn": { "x": 0, "y": 0, "facing": "right" }
}
```

- 正式數值須在建築透明圖完成後量測，以上零值只是欄位格式，不是實際座標。
- 指定入口出生在房門側邊稍遠處，角色以側臉面向房門；不得出生即觸發對話框。
- 返回出生點靠近剛離開房間，但仍須保留安全距離及可移動空間。
- 點擊建築時，角色前往 `doorApproach`，不是建築圖片中心。

## 8. Y 軸排序與遮擋

- 人物排序使用腳底中心的地圖 Y 值。
- 低於人物腳底的前牆、門柱、屋簷或樹冠放入 `building-foreground`／`boundary-front`。
- 室內核心家具若允許人物繞行，須各自提供排序基準；若只作背景展示，併入 `building-back`。
- 不以整棟建築單張圖片解決所有遮擋，避免人物站到房門側面時錯誤蓋住房名或牆體。

## 9. 正式素材驗收

- 四棟大小與 v5 相對比例一致。
- 中央保留移動及對話框空間。
- 四個入口皆能由側面接近，人物不遮住房間主要識別物。
- 人物光環中心、陰影與雙腳接地點在所有動畫格一致。
- 人物不穿牆、不被透明屋頂區阻擋，也不會卡在植栽或建築邊角。
- 點擊移動、WASD／方向鍵及觸控操作使用同一套碰撞資料。
- Enter 只在房門觸發區或確認視窗中生效。
- 桌面、平板橫向及手機均無裁掉必要入口或操作安全區。

## 10. 製作順序

1. 正式滿版地貌與邊界分層；地貌不含入口道路或對齊地磚。
2. 四棟建築透明分層稿。
3. 依正式圖層量測建築碰撞、入口、出生與返回位置。
4. 依 v5 比例製作阿岳正式待機與步行精靈。
5. 製作腳邊光環、陰影及偵錯模式線框。
6. 將正式素材接入已通過的地圖技術原型。
7. 完成桌面、平板橫向、手機與四入口往返驗收。
